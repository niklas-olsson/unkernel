# The AArch64 CPU (src/a64)

kwemu's guest CPU: A64, ARMv8.0-A user mode (EL0), little-endian, FP and
AdvSIMD, plus the optional AES, PMULL, SHA1, SHA2, CRC32, LSE, SHA512 and
SHA3. No SVE, pointer authentication or MTE (their hint-space encodings,
PACIASP, AUTIASP, BTI, XPACLRI, run as NOPs). The contract is
`include/kw_emu.h` (ABI 3): `struct kw_regs` is the A64 register file and
`kw_run` the A64 run loop. Three tiers:

- the **reference interpreter** (`run.runRef`, `decode.exec`): raw bits to
  semantics, one instruction at a time; the semantic oracle;
- the **decoded-op tier** behind `kw_run` (`tier.run`): decodes blocks once
  into 16-byte ops and runs what has no op (`generic`) through the
  reference;
- the **JIT**: compiles hot decoded blocks to wasm (every op kind, the
  frequent `generic` ops inline, the rest as calls of the reference).

What lies under them (MMU, TLBs, block cache, JIT core, softfloat) is
ISA-neutral and in kwemu.md.

## Layout

`decode.zig` routes each word by the Arm ARM's encoding tables to exactly
one group file; it is complete and needs no change when instructions are
added. Each group file owns its decode and semantics, exposes
`pub fn exec(s: St, inst: u32) Error!Exit`, and returns `ill(s, inst)` for
everything it does not implement. Keep each instruction's semantics in a
function that takes decoded operands (`dp_imm.addSub`,
`dp_imm.bitfieldOp`, `dp_reg.sdiv`, ...) so the tiers can call the same
code.

## Conventions for group files

- **Exits.** `.next`: retired, the dispatcher adds 4 to pc. `.jump`: a
  taken branch that set `s.r.pc` (`jump(s, target)`). `.trap`: did not
  retire, pc unchanged (`ill`, `misaligned`, `breakpoint`; `syscall`
  retires). The reference loop polls interrupts after every `.jump` and
  every 64 instructions.
- **Registers.** Register 31 is XZR or SP by operand: `xr`/`reg`/`setX`/
  `setR` for XZR forms, `xsp`/`regSp`/`setXsp`/`setRsp` for SP forms.
  `setR(s, sf, n, v)` zero-extends W results. V registers: `vq`/`setVq`
  (128 bits), scalar `setVd/Vs/Vh/Vb` zero the rest, `setVec(s, n, q, v)`
  zeroes the top half when Q = 0, `lanes(T, v)`/`fromLanes`/`lane`/
  `setLane`/`v128(lo, hi)` for elements.
- **No compiler-rt calls.** No u128 shifts by a variable amount, no u128
  multiply or divide, no `(x << 64) | x` built from integers (LLVM makes a
  multiply), no u128 lane picked by a run-time index (`c.lane` with a
  variable index becomes `__lshrti3`; select the 64-bit half with a mask).
  On wasm these are calls (`__ashlti3`, `__multi3`) the kernel does not
  link. `fromLanes`/`v128` go through vectors and are safe. Avoid copying
  arrays of 64 bytes or more by value (`buf = f(buf)`, a returned
  `[8]u64`) and initialising large structs by value: on wasm each becomes
  a `memory.copy` or `memory.fill`. Fill such buffers in place through a
  pointer.
  `test/a64-test.mjs` fails if `kwemu.o` or `kwemu-jit.o` imports any
  function.
- **Flags.** `nzcv` holds N, Z, C, V in bits 31..28. `addWithCarry(sf, a,
  b, carry)` returns the result and the flags (pass `~b, 1` for
  subtraction), `nzLogic` for logical ops, `condHolds(nzcv, cond)`.
- **Operands.** `shiftReg(sf, v, type, amount)`, `extendReg(v, option,
  shift)`, `decodeBitMasks(N, imms, immr, immediate, datasize)` (null where
  the Arm ARM is UNDEFINED), `replicate`, `sextN`, `bits(inst, hi, lo)`.
- **Precise faults.** An instruction that faults or traps has no effect:
  load everything into locals first, write registers last. A single
  `load`/`store` (up to 64 bits, unaligned and page-straddling allowed) is
  all or nothing; for several stores call `probeWrite(s, va, len)` over
  the whole range first (`store128`, pairs, DC ZVA do). `checkAlign(s, va,
  size)` raises KW_EV_MISALIGNED (exclusives, LDAR/STLR, LSE).
- **FP.** Use `fparith.zig` (scalar and AdvSIMD alike): pure functions of
  raw bits and the FPCR value that apply every Arm rule (NaN order and DN,
  FZ with IDC/UFC, tininess before rounding, AHP, saturating conversions)
  and OR FPSR bits into a `fl` accumulator; write `s.r.fpsr |= fl` once,
  after anything that can fault. Its header lists the API. Underneath,
  `fpu.F32`/`fpu.F64` follow RISC-V (common.zig's `fpRound`/`fpRaise` map
  it), so code calling fpu directly must add the Arm rules: propagate NaN
  operands unless FPCR.DN (`processNaN`, `processNaNs`, `processNaNs3`,
  before the arithmetic); tininess before rounding (fpu detects it after);
  FZ and AHP. Linux starts tasks with FPCR = 0.
- **Optional features** (`Feature`, the `KW_ISA_*` bits). Decode a
  feature's encodings behind `has(s, .aes)`, else `ill`. Add it to
  `common.implemented` only when it is complete and tested: `kw_set_isa`
  then enables it and the kernel advertises it in AT_HWCAP and
  ID_AA64ISAR0_EL1 (a64/isa.md). `consistentIsa` drops SHA512 from a set
  without SHA2. The tier never gives an optional instruction its own op
  kind (decoded blocks do not depend on `kw_set_isa`, which resets the
  cache anyway).

## Adding things

- **An instruction**: in its group file, behind the reference's legality
  checks; a unit test in `tests.zig` (`machine.zig`: `m.code(va, words)`,
  `m.mapData`, `m.run(budget)`) and a form in the guest that covers its
  class (compared with qemu). It runs as `generic` in the tier and as an
  interpreter call in compiled code until something faster is wanted.
- **A tier op kind** (when a `generic` instruction is hot): a64/tier.md,
  Adding an op. It needs its JIT family too.
- **A JIT translation of a generic op**: generic.zig, vec.zig or
  atomic.zig (a64/jit.md), with a kindtest line.
- **A guest**: `test/guest/a64/<name>.c`, its name in `a64_guests` in
  build.zig, an entry in `cases` in `test/a64-test.mjs`. Guests must not
  print what differs between qemu and kwemu by design (stack or random
  addresses, MIDR, HWCAP). They are built static for `aarch64-linux-musl`
  with the generic (v8.0) cpu and `-fno-vectorize -fno-slp-vectorize`
  (zig's libc itself uses some NEON).

## Tests

`zig build test` runs:

- the A64 unit tests (`src/tests_a64.zig`: every `*tests*.zig`, the tier's
  block fuzz, the JIT family tests; native, ReleaseSafe);
- `a64-unit-jit`: the same as wasm64 through `test/kwemu-unit-wasm.mjs
  --name a64` with the eager host of `test/kwemu-jit-host.mjs` (only tests
  whose names contain `a64 tier` or `a64 jit`, so name JIT tests so), and
  `a64-nosimd` again with a host without SIMD (`KWEMU_JIT_SIMD=0`);
- `test/a64-test.mjs`: every guest in `zig-out/guest/a64` under
  qemu-aarch64 (or `$QEMU_AARCH64`; without it a skip note and only exit
  statuses are checked) and under the harness: native and wasm64 through
  kw_run's tier; wasm64 with the JIT eager, at the threshold, without SIMD
  (`wasm64+jit/nosimd`) and lowered to memory32 (needs `$WASM_OPT` or
  `vendor/toolchain/binaryen/bin/wasm-opt`, else a skip note), each
  retiring exactly the interpreter's instruction count; and native
  `--lockstep 1` (the tier and the reference loop side by side, compared
  at every event). Same stdout and exit status everywhere.

Build options for tests: `-Dkwemu-a64-ref` (kw_run is the reference loop,
for a kernel to compare against), `-Dkwemu-a64-fuzz=N
-Dkwemu-a64-fuzz-seed=S` (more block-fuzz programs; it prints every 64th
seed, a panic does not name one).

| Guest | Covers |
| --- | --- |
| `hello.c` | startup, stdio, TLS, exit status |
| `inttest.c` | each integer form over edge and random values, one hash per form (a differing line names the form) |
| `fptest.c` | Arm FP known answers (exit status = failures), every scalar FP form under each rounding mode with FZ, DN and AHP; `fptest fuzz <seed> <count>` prints one line per random case to diff against qemu |
| `simdtest.c` | every AdvSIMD integer form (6228 words) over boundary register states; `simdtest v` one hash per word, `w` mode for the fuzz |
| `simdfptest.c` | every AdvSIMD FP form (1266 words) over 48 FP edge states, each with its own FPCR |
| `simdmovetest.c` | every form of simd_move and simd_ldst (arrangements, lanes, post-index, register lists wrapping at V31) |
| `cryptotest.c` | AES, SHA1, SHA256, SHA512, SHA3/SHAKE, CRC32 known answers, then one hash per form; ignores HWCAP |
| `atomictest.c` | musl's atomics on LDAXR/STLXR, 128-bit CAS by LDAXP/STLXP, LDAR/STLR, CNTVCT, DC ZVA, code rewritten and made visible by DC CVAU + IC IVAU |
| `lsetest.c` | every LSE encoding (290 hashes), known answers set the exit status |
| `bench.c` | sieve+fib benchmark (also `test/guest/kbench.c` modes; a64/performance.md) |

By hand: `node test/a64-simd-fuzz.mjs [--fp] [count] [seed]` draws random
words from the AdvSIMD classes and compares legality (classifier against
`qemu-aarch64 -cpu cortex-a53`) and results (simdtest / simdfptest `w`
mode on the native harness). Decodes were also checked against llvm-mc's
disassembler over whole encoding spaces (a64/isa.md).

The kernel side adds kwtest checks (kernel/tests.md): system registers, FPCR
masks, LSE and exclusives on 2-4 CPUs, the JIT's cross-CPU code rewrite.
